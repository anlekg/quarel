# Corrections de l'audit (2026-09-26) — Guide de test

Ce qui a changé et comment le vérifier à la main. Les tests automatiques couvrent déjà chaque point (`make test`, `make e2e-dm-groups`, `make e2e-client`).

## 1. Connexion aux serveurs (faille principale)
- Rejoindre un serveur **auto-signé** depuis l'application de bureau : rien ne change.
- Un serveur **Let's Encrypt** (ou derrière un proxy) : il doit connaître son nom. Derrière un proxy, renseigner « Nom public du serveur » (`QUAREL_TLS_HOSTS`) dans la page d'administration, sinon l'application affiche « Ce serveur ne répond pas sous cette adresse ». Le tableau de bord le rappelle.
- Deux serveurs **auto-signés** sur le **même nom** (ports différents) ne sont plus possibles depuis l'application : utiliser deux noms (ex. l'IP et un nom DynDNS).

## 2. Page d'administration
- Sur la machine elle-même : `http://localhost:8091` (ou 8081) fonctionne comme avant.
- Depuis un autre appareil du réseau : `http://<ip>:8091` **redirige vers `https://<ip>:8091`**. Accepter l'avertissement du navigateur (certificat auto-signé) ; son empreinte SHA-256 est dans le journal du serveur (« Empreinte du certificat »).
- Ouvrir la page avec un nom inconnu (ex. une entrée ajoutée dans le fichier hosts) : refus « Nom d'hôte inconnu ».

## 3. Messages privés : confiance
- Conversation en tête à tête → bouton **bouclier** : les deux personnes voient le **même code**. « Les codes correspondent » → badge **Vérifié**.
- Groupe → bouton **+** : ajouter un ami ; les autres voient « X a ajouté Y au groupe » et Y lit les messages suivants.
- « J'ai tout perdu » (bandeau d'un appareil non validé) : nouvelles clés après mot de passe (et 2FA). Chez un contact : l'envoi est bloqué, le bouton « Comparer le code de sécurité » montre le nouveau code, « accepter la nouvelle clé » débloque. Un email d'alerte arrive.

## 4. Comptes
- Se tromper de mot de passe 100 fois depuis ailleurs ne bloque plus un appareil déjà connecté au compte (difficile à tester à la main : couvert par les tests).
- S'inscrire avec une adresse déjà utilisée : même réponse qu'une inscription normale, et la personne reçoit un email « tentative d'inscription ».
- Se déconnecter d'un appareil (ou le retirer dans Paramètres › Appareils) : ses sessions sur les serveurs communautaires se ferment **dans les 10 minutes**.

## 5. Stockage
- Page d'administration › Réglages : « Espace disque réservé » (1 Go par défaut) sur les deux serveurs ; côté identité, quotas des copies de fichiers et des messages en attente.

## 6. Serveurs communautaires
- Propriétaire : clic sur un membre › **Transférer la propriété**. Le serveur change de propriétaire, l'ancien reste membre.
- Page d'administration › Tableau de bord › **Réinitialiser le propriétaire** : un nouveau lien propriétaire s'affiche.

## 7. Suites de l'audit (2026-09-27)
- Actions GitHub épinglées par empreinte de commit (`.github/workflows/ci.yml`, mises à jour par Dependabot).
- Validation d'intégrité de `app.asar` activée pour les versions Windows publiées à partir de la prochaine. **À essayer sur votre PC Windows avant qu'on publie** : installez `https://quarel.app/telechargements/test/Quarel-Setup-0.3.0-test-integrite.exe` (même version 0.3.0, vos données sont gardées), lancez Quarel, connectez-vous, ouvrez un serveur et vos messages privés. Si tout marche comme d'habitude, c'est bon ; si Quarel refuse de démarrer, dites-le avant toute publication.

## 8. Relecture (version 0.3.0)
- Un serveur resté en 0.2.0 : l'application 0.3.0 affiche « Ce serveur utilise une version de Quarel trop ancienne… » au lieu de « Connexion perdue ». Son hébergeur doit le mettre à jour.
- Deux serveurs sur la même machine : donnez-leur des ports vocaux différents (Réglages › Vocal et vidéo, dont le nouveau « Port de signalisation (local) ») ; sinon le vocal du second reste indisponible et son journal l'indique (« voice unavailable »).
